v9.8.0 引入了 **DA-ECP (Data Analysis Enhanced Construction Protocol)**，彻底改变了系统处理数据的方式。我们不再盲目地在构建时生成假数据，而是专注于 **"构建时理解，问答时造数"**。

---

## 🚀 核心理念：动静分离

### 🏗️ 构建阶段：建筑师模式 (The Architect)
在您点击 "立即创建" 时，系统执行的是 **"冷处理"**：
1.  **嗅探 (Sniffing)**: 区分文件是 "真实记录" (Solid) 还是 "规则定义" (Virtual)。
2.  **画像 (Profiling)**: 对真实数据计算 `Min/Max/Avg` 和 `Null Rate`。
3.  **解析 (Parsing)**: 对字典文件提取 `Column Name` 和 `Comment`。
4.  **固化 (Solidification)**: 将所有逻辑写入 `business_schema.json`，**不生成任何模拟数据**。

### ⚡ 问答阶段：魔术师模式 (The Magician)
在您提问 "分析华东地区金牌用户趋势" 时，系统执行 **"热生成"**：
1.  **检测**: 发现 `users` 表是空的（因为它是 Virtual Table）。
2.  **JIT 造数**: 根据 Schema 定义，结合您的问题（"华东", "金牌"），**现场生成** 30 条符合条件的模拟数据。
3.  **分析**: 执行 SQL，返回精准的趋势图表。

## 📖 最佳实践

### 场景 1：混合构建 (推荐)
同时上传 **`sales_2023.csv` (真实数据)** 和 **`data_dictionary.xlsx` (字典)**。
- **效果**: 系统会用字典里的注释（如 `status: 1=已支付`）来理解真实数据，Text-to-SQL 准确率提升 100%。

### 场景 2：纯虚构推演
只上传 **`product_design.md` (需求文档)**。
- **效果**: 系统会自动提取表结构。当您问 "如果库存不足会怎样？" 时，系统会生成 "库存=0" 的模拟数据来进行沙盘推演。

## 🛠️ 故障排查

### Q: 为什么 `business_data.db` 是空的？
**A**: 正常现象。请参考“动静分离”原则。数据只在需要时存在。

### Q: 为什么回答时显示 "正在确保业务底座完整性"？
**A**: 这说明 JIT 引擎正在工作，为您补充缺失的数据。这是系统健康的标志。
