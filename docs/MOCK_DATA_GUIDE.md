# 🎭 虚拟数据生成 (Mock Data) 全攻略

**版本**: v6.7.0 
**状态**: 核心功能组件

当您只有业务逻辑描述（PDF/MD）而没有实际数据，或者需要快速验证分析模型时，RAG Pro Max 的**虚拟数据生成引擎**将为您提供物理级的底座支撑。

---

## 🚀 5分钟快速上手

### 场景：您只有表结构需求，没有实际数据

**传统方案**: 系统提示“未找到记录”，分析中断。
**当前方案**: 
1. **构建阶段**: 系统自动推演逻辑，生成 30+ 条仿真数据。
2. **对话阶段**: SQL 直接查询物理库，秒级返回可视化结果。

### 操作步骤
1. **准备 Schema**: 
   - **方式A**: 上传 DDL SQL 文件。
   - **方式B**: 上传包含表头但无数据的 Excel/CSV。
   - **方式C**: 在 PDF/MD 文档中用文字描述业务表结构。
2. **构建知识库**: 开启“数据分析”模式并点击构建。
3. **开始问答**: 直接针对您的业务表进行统计提问。

---

## 🏗️ 核心工作原理 (Build-First)

系统不再将造数推迟到“提问时”，而是遵循 **“构建期物理闭环”**：

1. **逻辑提取**: AI 扫描文档，提取 `TABLE` 和 `COLUMN` 定义。
2. **物理建表**: 在 `business_data.db` 中创建真实的 SQLite 表。
3. **双轨注入**:
   - **LLM 注入 (主方案)**: AI 根据业务背景（如：金融、医疗）生成逻辑自洽的记录。
   - **规则注入 (备用)**: 若 LLM 调用受限，系统自动根据字段名（如 `price`, `date`）填充符合类型的占位数据。
4. **就绪声明**: 控制台打印 `✨ [Success] 数据分析物理底座构建完成`。

---

## 🔍 故障排查 (Troubleshooting)

### Q: 显示“未产生回显数据”？
- **原因**: 可能是 WHERE 条件过于苛刻。
- **排查**: 检查 `business_schema.json` 中的字段取值建议，或查看 SQL 源码中的具体过滤条件。

### Q: 生成的数据不符合预期逻辑？
- **优化**: 在上传的文档中增加对字段的详细说明（例如：`status 字段只能取 [已完成, 待支付]`）。系统会自动捕获这些指纹并注入仿真引擎。

---

## 🛠️ 管理与维护
- **数据持久化**: 生成的数据保存在 `vector_db_storage/{KB_NAME}/business_data.db`。
- **手动修复**: 您可以使用标准的 SQLite 工具直接修改或补充该数据库。
