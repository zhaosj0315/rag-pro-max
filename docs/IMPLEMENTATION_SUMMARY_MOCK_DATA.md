# 虚拟数据生成功能实现总结

## 📋 需求背景

用户反馈：在数据分析模式下，如果上传的表只有结构没有实际数据，系统会返回空查询结果，影响用户体验。

**期望行为**：
- 如果表有数据 → 直接使用真实数据
- 如果表无数据 → 自动生成虚拟数据，然后查询并回答

## ✅ 实现方案

### 1. 核心修改

修改文件：`src/processors/data_analyst.py`

#### 新增方法

**`_generate_mock_data()`** - LLM 驱动的数据生成
- 根据表结构、字段说明和业务背景生成 INSERT 语句
- 使用 LLM 确保数据真实合理
- 支持复杂的业务逻辑和数据关联

**`_generate_simple_mock_data()`** - 规则引擎备用方案
- 基于字段名关键词匹配生成数据
- 不依赖 LLM，稳定可靠
- 适用于简单场景和 LLM 失败时的降级

#### 优化方法

**`_ensure_sandbox_ready()`** - 数据检查与生成逻辑
- 改进表数据检查逻辑
- 区分"表不存在"和"表为空"两种情况
- 统一处理数据生成流程
- 增强日志输出，提供清晰的状态反馈

### 2. 工作流程

```
检查表状态
    ↓
┌─────────────────┬─────────────────┬─────────────────┐
│ 表不存在        │ 表存在但为空    │ 表有数据        │
├─────────────────┼─────────────────┼─────────────────┤
│ 1. 创建表结构   │ 1. 保留表结构   │ 直接使用        │
│ 2. 尝试 LLM 生成│ 2. 尝试 LLM 生成│                 │
│ 3. 失败则用规则 │ 3. 失败则用规则 │                 │
│ 4. 提交数据     │ 4. 提交数据     │                 │
└─────────────────┴─────────────────┴─────────────────┘
```

### 3. 数据生成策略

#### LLM 生成（主方案）
- 生成数量：30 条
- 提示词包含：表名、字段定义、业务背景、格式要求
- 优点：数据真实、符合业务逻辑
- 缺点：依赖 LLM，可能不稳定

#### 规则引擎（备用）
- 生成数量：20 条
- 基于字段名关键词匹配
- 支持的字段类型：
  - ID 字段 → ID0001, ID0002
  - 名称字段 → 测试1, 测试2
  - 日期字段 → 2025-01-01, 2025-01-02
  - 金额字段 → 1000, 2137, 3274
  - 状态字段 → 正常, 待审核, 已完成
  - 省份字段 → 广东, 上海, 北京
  - 行业字段 → 信息技术, 医疗健康

## 🎯 功能特点

### 优势
1. **零配置**：用户无需任何配置，系统自动检测并生成
2. **智能化**：LLM 驱动生成真实合理的数据

3. 系统演示和测试
4. 快速原型开发
