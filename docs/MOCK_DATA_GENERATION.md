# 虚拟数据自动生成功能说明

## 📋 功能概述

RAG Pro Max v6.6.5 的数据分析模式现在支持**智能虚拟数据生成**功能。当系统检测到相关表只有结构没有数据时，会自动生成合理的虚拟数据填充到数据库中，确保查询能够返回有意义的结果。

## 🎯 核心特性

### 1. 自动检测与生成
- **表不存在**: 自动创建表结构并生成数据
- **表为空**: 检测到空表时自动填充数据
- **表有数据**: 直接使用现有数据，不做修改

### 2. 智能数据生成
- **LLM 驱动**: 使用大语言模型根据表结构和业务背景生成真实合理的数据
- **备用方案**: 如果 LLM 生成失败，自动切换到规则引擎生成占位数据
- **数据量**: 默认生成 20-30 条记录，确保查询结果有代表性

### 3. 业务逻辑对齐
- 根据字段名和类型生成合理的值
- 考虑业务背景和表说明
- 保持数据之间的逻辑关联性

## 🔧 工作流程

```
用户提问
    ↓

│             │             │             │

```

## 📊 数据生成策略

### LLM 生成模式（主方案）
```python
# 提示词包含:
- 表名和说明
- 字段定义（名称、类型、注释）
- 业务背景（macro_context）
- 数据格式要求
- 逻辑关联要求
```

生成示例：
```sql
INSERT INTO mx_ztyp_ssy_ckxxxq VALUES ('C001', '华为技术有限公司', '信息技术', '广东', 2025, 31240000000);
INSERT INTO mx_ztyp_ssy_ckxxxq VALUES ('C002', '恒瑞医药股份有限公司', '医疗健康', '江苏', 2025, 19870000000);
```

### 规则引擎模式（备用方案）
根据字段名关键词自动匹配合适的值：

| 字段特征 | 生成规则 | 示例 |
|---------|---------|------|
| id | ID + 序号 | ID0001, ID0002 |
| name, 名称 | 测试 + 序号 | 测试1, 测试2 |
| date, 日期 | 当前年月 + 递增日 | 2025-01-01, 2025-01-02 |
| amount, 金额 | 序号 * 基数 + 随机数 | 1137, 2274 |
| status, 状态 | 预设状态列表循环 | 正常, 待审核, 已完成 |
| province, 省份 | 常见省份列表循环 | 广东, 上海, 北京 |
| industry, 行业 | 常见行业列表循环 | 信息技术, 医疗健康 |

## 🔍 使用场景

### 场景 1: 纯表结构导入
用户上传了只包含表结构的 SQL 文件或 Excel 模板：
```sql
CREATE TABLE orders (
    order_id TEXT,
    customer_name TEXT,
    amount REAL,
    order_date TEXT
);
```

系统行为：
1. 解析表结构
2. 自动生成 20-30 条订单数据
3. 用户可以立即进行查询分析

### 场景 2: 业务模型验证
用户定义了业务模型但还没有实际数据：
```json
{
  "tables": {
    "sales_data": {
      "desc": "销售数据表",
      "cols": [
        {"name": "product", "comment": "产品名称"},
        {"name": "sales", "comment": "销售额"}
      ]
    }
  }
}
```

系统行为：
1. 根据业务背景生成合理的产品和销售数据
2. 确保数据符合业务逻辑
3. 支持立即进行数据分析

### 场景 3: 演示和测试
用户需要快速演示系统功能：
- 无需准备真实数据
- 系统自动生成演示数据
- 查询结果真实可信

## ⚙️ 配置选项

### 数据量控制
在 `_generate_mock_data` 方法中修改：
```python
# 默认生成 30 条
prompt = f"""为数据表 '{table_name}' 生成 30 条真实、合理的测试数据。"""

# 备用方案生成 20 条
for i in range(20):
    # ...
```

### 禁用虚拟数据生成
如果需要禁用此功能，在调用时传入 `model_client=None`：
```python
mapping = engine._ensure_sandbox_ready(
    schemas, 
    model_client=None,  # 禁用虚拟数据生成
    conn=conn
)
```

## 📝 注意事项

1. **数据真实性**: LLM 生成的数据更真实，但可能不稳定；备用方案稳定但较简单
2. **性能影响**: 首次生成数据需要调用 LLM，可能需要几秒钟
3. **数据持久化**: 生成的数据会保存在 SQLite 数据库中，下次使用时不会重新生成
4. **数据覆盖**: 如果需要重新生成数据，需要先清空表或删除数据库文件
